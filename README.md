# 成品檢驗報工系統 V601.11.02

Windows 區域網路內使用的 Flask + SQLite 條碼報工系統。系統不依賴雲端服務；預設由一台主機提供網頁與資料庫，其他同網路電腦使用瀏覽器連入。

## 啟動

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
py -m pip install -r requirements.txt
py app.py
```

主機預設監聽區域網路（`0.0.0.0:5000`）。主機本機可開啟 `http://127.0.0.1:5000/`；其他同網路電腦請使用主機 IP，例如 `http://192.168.1.20:5000/`。校機資料庫位於主機的 `instance/inspection.db`，備份位於 `instance/backups/`。可用 `INSPECTION_DATA_DIR` 指定資料目錄；既有組裝資料庫 `instance/intjr.db` 不會被讀取或修改。

印表機電腦與掃碼電腦必須連到同一個主機網址，不能各自執行一份系統。若 Windows 防火牆跳出提示，允許 Python 在「私人網路」通訊；也可用 `INSPECTION_HOST=127.0.0.1` 恢復單機模式。

Windows 主機同一時間只允許一個主系統程序。重複啟動時，第二個程序不會建立 Flask 或開啟 SQLite，而是開啟既有系統網址並提示系統已在執行。

主系統啟動後會依台北日期建立每日自動備份；同一天最多一份，只保留最近 30 份 `inspection_auto_*.db`。手動建立的 `inspection_backup_*.db` 不會被自動輪替刪除。自動備份失敗會寫入 `instance/app.log`，但不會阻止系統啟動。

```powershell
pytest -q
```

## 重要設計

- 一張訂單對應一台機台及一次校機工作；訂單號碼唯一，機台製號可跨訂單重複。
- 建立訂單時不指定人員；助理列印訂單專用 START／FINISH 條碼，校機人員於掃描 START 時認領。
- 校機掃描固定為「員工條碼 → 訂單 START/FINISH」兩段流程；訂單條碼處理後清除暫存員工身分。
- 校機人員具有唯一員工編號、姓名與系統產生的 Code128 條碼；可編輯或刪除尚未產生歷史訂單的人員，停用人員不可執行新報工。
- 訂單條碼使用 12 字元短版 Code128 payload（START/FINISH 以訂單 ID 與 checksum 識別）；完整訂單資料留在主機資料庫。
- 訂單與員工條碼列印頁均以單張 60×60 mm 標籤為目標，列印時選擇實際大小／100%，仍需用現場熱感印表機確認可掃性。
- 訂單狀態為待校機、校機中、已完成、已取消；所有開始、完成、掃描與主檔操作均保留稽核紀錄。
- 機型可分類為四軸或五軸；首頁與報表會統計兩類台數，訂單明細及 Excel 會保留軸別。
- 軸別由系統自動判斷：機型 F／M 開頭或機台製號 S 開頭為五軸，其他為四軸。
- 報表支援訂單、機型、軸別、機台製號、人員及狀態篩選，Excel 匯出包含人員統計、軸別統計與訂單明細。
- 報表下方的訂單明細可進入編輯頁列印 Code、取消訂單或刪除尚未開始的誤建訂單；刪除前會自動備份，已開始或已完成的歷史訂單保留。
- 系統包含報表、備份/還原、掃描事件、稽核紀錄及員工/訂單條碼列印。
- 上方「清除資料」提供除錯用分類清除，執行前會先建立完整 SQLite 備份；正式資料也會依所選分類清除。

## 分階段實作紀錄

- Phase 0：專案骨架、啟動、SQLite、決策紀錄。
- Phase 1：獨立校機資料表、外鍵、索引與設定。
- Phase 2：機型、校機人員、員工條碼與訂單建立。
- Phase 3：訂單 START／FINISH 條碼、員工認領與狀態機。
- Phase 4：報表、人員統計、Excel、備份、還原與稽核。
- Phase 5：Windows 建置、現場掃描與標籤尺寸驗收。
