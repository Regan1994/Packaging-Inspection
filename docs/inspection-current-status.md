## 已完成

- 系統名稱及介面已改為「TJR校機報工系統」與「成品檢驗報工」語意。
- 主機預設監聽 `0.0.0.0:5000`；主機本機使用 `127.0.0.1`，其他電腦使用主機區網 IP。可用 `INSPECTION_HOST=127.0.0.1` 切回單機模式。
- Windows 使用全域命名 Mutex 限制主機只能執行一個主系統程序；重複啟動不會建立 Flask 或開啟 SQLite，而會開啟既有網址並顯示提示。Mutex 由作業系統管理，程序結束或異常中止後會自動釋放，不使用 lock file。
- 主系統啟動後依台北日期每日建立一份經 SQLite backup API 產生並通過 `integrity_check` 的自動備份；只輪替 `inspection_auto_*.db`，保留最近 30 份，不刪除 `inspection_backup_*.db` 手動備份。失敗會記錄於 `instance/app.log`，但不阻止啟動。
- 訂單明細提供管理員修正：可更正誤掃人員、START／FINISH，補登或修正缺料、補料、人工暫停與恢復時間。每次操作都重新驗證管理密碼、要求修改人與原因、修改前建立完整備份，並在稽核紀錄保存舊值、新值及備份路徑；暫停區間不可重疊，尚未恢復時不可補登 FINISH。
- 校機資料只使用獨立的 `instance/inspection.db` 與 `instance/backups/`；不讀取或修改既有組裝用 `instance/intjr.db`。
- 建立訂單時不指定人員；輸入唯一訂單號碼、機型與機台製號，機台製號可跨訂單重複。
- 機型主檔前台只輸入及顯示名稱；內部機型代碼由系統自動產生並保留在資料庫，不要求現場人員維護。
- 軸別由規則自動判斷：機型名稱 F／M 開頭，或機台製號 S 開頭為五軸，其他為四軸；首頁、報表及 Excel 可統計四軸與五軸台數。
- 訂單建立後產生 START／FINISH 兩張短版條碼；訂單條碼 payload 為 12 字元，完整訂單資料留在 SQLite。
- 掃描流程固定為「員工條碼 → 訂單 START/FINISH」；訂單條碼處理後清除該瀏覽器的暫存員工身分。
- 新增固定「缺料／補料」條碼；操作流程為「員工條碼 → 缺料或補料 → 該訂單 START」，可記錄多段缺料區間。缺料期間停止累計實際工時，尚未補料時禁止 FINISH。
- START 會在掃描當下綁定啟用中的校機人員；FINISH 預設只允許原認領人員。
- 停用人員不可開始或完成新的報工，既有訂單的人員 snapshot 與歷史資料保留。
- 訂單狀態包含待校機、校機中、已完成、已取消；重複掃描、無效條碼、不存在訂單及時間順序錯誤會拒絕且寫入掃描紀錄。
- 支援機型、人員、訂單、條碼重印、固定缺料／補料條碼列印、報表篩選、校機人員統計、Excel 匯出、備份/還原、掃描事件、稽核紀錄及分類清除。
- 報表與 Excel 會分別顯示總經過時間、缺料時間及依正常班計算的實際校機工時；訂單編輯頁可查看每段缺料及補料紀錄。
- 實際校機工時目前只計算平日 08:00～17:00 的工作區間，暫扣除 12:00～13:00 午休；晚上、午休、週末及尚未定義的加班時間不計入。
- 訂單編輯頁提供「補登開始時間」：可選擇校機人員並輸入實際開始時間，將待校機訂單改為校機中；補登原因會寫入稽核紀錄。
- 報表下方的訂單明細可進入編輯頁列印 Code、取消待校機／校機中的訂單，或刪除尚未開始的誤建訂單；刪除前自動建立備份並保留刪除稽核紀錄，已開始或已完成的訂單不能刪除。
- 校機人員可編輯員工編號與姓名；沒有歷史訂單的人員可刪除，有歷史訂單的人員須停用以保留歷史紀錄。
- 訂單與員工條碼列印頁設定為單張 60×60 mm 標籤；CSS 已限制頁面尺寸與條碼版面。
- 首頁左下角顯示目前版本；現行開發與發布包版本為 `V602.11.02`。
